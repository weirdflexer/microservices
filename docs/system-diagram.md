# Система бронирования бильярдных столов: текстовая диаграмма

Источник: [интерактивная схема Unidraw](https://unidraw.io/app/board/a18abd92f9162767444e). Статичные картинки и сиреневые карточки с правилами не включены.

Здесь собран итоговый вариант: связи с доски, их исправления и необходимые дополнения объединены. `~` — уточнено, `+` — добавлено; без отметки — сохранено. Повторяющиеся команды объединены, опечатки в названиях исправлены.

**Как читать:** команда — что нужно сделать; событие — что уже произошло; запрос — какие данные нужно получить. `sync` означает вызов с ожиданием результата, `async` — передачу сообщения без ожидания завершения работы получателя. Результат запроса чтения не обязательно является отдельным доменным событием.

## Общая картина

```text
Клиент
  │
  ├── Пользователь: регистрация, профиль, контакты
  ├── Тарифы: расчёт стоимости → ценовое предложение
  │
  └── Бронирование: создать заявку
        │
        ├── sync → Пользователь: получить данные клиента
        ├── sync → Тарифы: проверить ценовое предложение
        └── sync → Расписание: удержать интервал
                     └── sync → Каталог столов: проверить стол
        │
        └── async → Платежи: создать платёж
                       └── Платёжный провайдер: провести оплату
                              │
                  результат → Платежи
                              └── async → Бронирование
                                            │
                                            └── sync → Расписание:
                                                       закрепить интервал
                                            │
                                      Бронь подтверждена
                                            │
                     ┌──────────────────────┴─────────────────────┐
                     ▼ async                                      ▼ async
               Игровые сеансы                               Уведомление
               создать посещение                            создать сообщение
                     │                                            │
               начать / завершить / неявка                  sync → Пользователь:
                     │                                      получить контакт
                     └── async → Бронирование                      │
                                 завершить бронь            Провайдер сообщений
```

При отмене Бронирование освобождает интервал, отменяет ожидаемое посещение и при необходимости запускает возврат через Платежи. При истечении удержания Расписание сообщает об этом Бронированию, которое закрывает просроченную бронь.

## Участники и внешние сервисы

| Участник | Что делает |
|---|---|
| Клиент | Регистрируется, меняет профиль и контакты, получает стоимость, оформляет и отменяет бронь, оплачивает её. |
| Администратор | Управляет столами и расписанием, отмечает начало и завершение игрового сеанса. |
| Управляющий | Публикует тарифы. |
| Таймер | Запускает обработку просроченного удержания и фиксацию неявки. Это внутренний инициатор, а не отдельный бизнес-микросервис. |
| Платёжный провайдер | Внешний сервис проведения оплаты и возврата денежных средств. |
| Провайдер сообщений | Внешний сервис доставки уведомлений клиентам. |

## S1. Пользователь

**Основная сущность:** Пользователь. **Назначение:** данные клиента, профиль и контакты.

| Команда или запрос | Событие или результат |
|---|---|
| Зарегистрироваться | Клиент зарегистрирован. |
| Изменить профиль | Профиль изменён. |
| Изменить контакт | Контакт изменён. |
| Получить данные — запрос | Возвращены данные пользователя, в том числе нужные контакты. На доске результат подписан «Данные получены». |

## S2. Каталог столов

**Основная сущность:** Бильярдный стол. **Назначение:** сведения о столах и их характеристиках.

| Команда или запрос | Событие или результат |
|---|---|
| Добавить стол | Стол добавлен. |
| Опубликовать стол | Стол опубликован. |
| Изменить карточку стола | Карточка стола изменена. |
| Получить сведения о столе — запрос `+` | Возвращены сведения, позволяющие проверить существование стола и возможность его бронирования. |

## S3. Расписание

**Основная сущность:** Расписание стола. **Назначение:** свободные, временно удержанные и закреплённые интервалы.

| Команда | Событие |
|---|---|
| Задать расписание стола | Расписание стола задано. |
| Удержать интервал | Интервал временно удержан **или** в удержании интервала отказано. |
| Закрепить интервал за бронью | Интервал закреплён за бронью. |
| Освободить интервал | Интервал освобождён. |
| Завершить просроченное удержание | Срок удержания истёк. |

## S4. Бронирование

**Основная сущность:** Бронирование. **Назначение:** жизненный цикл заявки и брони, связь с оплатой и посещением.

| Команда или запрос | Событие или результат |
|---|---|
| Создать заявку на бронь | Заявка на бронь создана. |
| Отклонить заявку | Заявка отклонена. |
| Открыть ожидание оплаты | Бронь ожидает оплаты. |
| Подтвердить бронь | Бронь подтверждена. |
| Закрыть просроченную бронь | Срок оформления брони истёк. |
| Отменить бронь | Бронь отменена. |
| Завершить бронь | Бронь завершена. |
| Завершить бронь по неявке | Бронь закрыта по неявке. |
| Сохранить данные созданного платежа `+` | Сохранены идентификатор платежа и данные, необходимые клиенту для оплаты. |
| Учесть неуспешную попытку оплаты `+` | Сохранён результат попытки оплаты. |
| Обработать результат возврата `+` | Обновлён статус возврата по брони. |
| Получить бронь — запрос `+` | Возвращены состояние брони и необходимые сведения о ней; для клиента также могут возвращаться данные для оплаты. |

## S5. Тарифы

**Основные сущности:** Тариф, Ценовое предложение. **Назначение:** тарифы, расчёт и проверка предложенной стоимости.

| Команда или запрос | Событие или результат |
|---|---|
| Опубликовать тариф | Тариф опубликован. |
| Рассчитать стоимость — запрос с формированием предложения | Ценовое предложение сформировано; клиенту возвращена рассчитанная стоимость. |
| Проверить ценовое предложение — запрос `+` | Возвращён результат проверки предложения для оформляемой брони. |

## S6. Платежи

**Основная сущность:** Платёж. **Внешний сервис:** Платёжный провайдер. **Назначение:** создание платежей, учёт результатов оплаты и возвратов.

| Команда | Событие |
|---|---|
| Создать платёж | Платёж создан. |
| Обработать результаты оплаты | Оплата получена **или** попытка оплаты отклонена. |
| Запросить возврат | Возврат запрошен. |
| Обработать результат возврата | Деньги возвращены **или** возврат не выполнен. |

## S7. Игровые сеансы

**Основная сущность:** Посещение. **Назначение:** ожидаемое посещение, фактическая игра и неявка.

| Команда | Событие |
|---|---|
| Создать ожидаемое посещение | Посещение ожидается. |
| Начать игровой сеанс | Игровой сеанс начат. |
| Завершить игровой сеанс | Игровой сеанс завершён. |
| Зафиксировать неявку | Неявка зафиксирована `~`. |
| Отменить ожидаемое посещение `+` | Ожидаемое посещение отменено `+`. |

## S8. Уведомление

**Основная сущность:** Уведомление. **Внешний сервис:** Провайдер сообщений. **Назначение:** подготовка, планирование и отправка сообщений клиенту.

| Команда | Событие |
|---|---|
| Создать уведомление | Уведомление подготовлено. |
| Запланировать напоминание | Напоминание запланировано. |
| Отправить уведомление | Уведомление отправлено **или** отправка уведомления не удалась. |

## Единый список межсервисных связей

### Оформление и оплата

| № | Откуда → куда | Тип | Что подразумевает связь |
|---|---|---|---|
| 1 | **S4 Бронирование: «Создать заявку на бронь» → S1 Пользователь: «Получить данные»** | sync | Получить данные клиента для оформления заявки. |
| 2 `~` | **S4 Бронирование: «Создать заявку на бронь» → S5 Тарифы: «Проверить ценовое предложение»** | sync | Проверить предложение, по которому клиент оформляет бронь. |
| 3 `+` | **S3 Расписание: задание расписания или удержание интервала → S2 Каталог столов: «Получить сведения о столе»** | sync | Проверить, что стол существует и допускается к бронированию. |
| 4 `~` | **S4 Бронирование: создание заявки → S3 Расписание: «Удержать интервал»** | sync | Временно занять выбранный интервал. Получить результат: удержан или отказано; при отказе отклонить заявку. |
| 5 `~` | **S4 Бронирование: «Бронь ожидает оплаты» → S6 Платежи: «Создать платёж»** | async | Передать запрос на создание платежа для конкретной брони. |
| 6 `+` | **S6 Платежи: «Платёж создан» → S4 Бронирование: «Сохранить данные созданного платежа»** | async | Передать идентификатор платежа и ссылку либо другие данные для оплаты. |
| 7 | **S6 Платежи: «Оплата получена» → S4 Бронирование: «Подтвердить бронь»** | async | Передать успешный результат оплаты и запустить подтверждение соответствующей брони. |
| 8 `+` | **S4 Бронирование: «Подтвердить бронь» → S3 Расписание: «Закрепить интервал за бронью»** | sync | Преобразовать действующее удержание в закреплённый интервал. Подтверждение брони завершается после успешного ответа. |
| 9 `+` | **S6 Платежи: «Попытка оплаты отклонена» → S4 Бронирование: «Учесть неуспешную попытку оплаты»** | async | Передать результат неуспешной попытки, связанный с её платежом и бронью. |

### Подтверждение, посещение и уведомление

| № | Откуда → куда | Тип | Что подразумевает связь |
|---|---|---|---|
| 10 `+` | **S4 Бронирование: «Бронь подтверждена» → S7 Игровые сеансы: «Создать ожидаемое посещение»** | async | Создать ожидаемое посещение по подтверждённой брони. |
| 11 | **S4 Бронирование: «Бронь подтверждена» → S8 Уведомление: «Создать уведомление»** | async | Подготовить клиенту сообщение о подтверждении брони. |
| 12 | **S8 Уведомление: подготовка или отправка сообщения → S1 Пользователь: «Получить данные»** | sync | Получить нужный контакт клиента для доставки уведомления. |
| 13 `~` | **S7 Игровые сеансы: «Начать игровой сеанс» → S4 Бронирование: «Получить бронь»** | sync | До начала игры проверить состояние и принадлежность брони нужному посещению. |
| 14 `+` | **S7 Игровые сеансы: «Игровой сеанс завершён» → S4 Бронирование: «Завершить бронь»** | async | Закрыть бронь после фактического завершения игры. |
| 15 `~` | **S7 Игровые сеансы: «Неявка зафиксирована» → S4 Бронирование: «Завершить бронь по неявке»** | async | Закрыть бронь по результату уже зафиксированной неявки. |

### Истечение срока, отмена и возврат

| № | Откуда → куда | Тип | Что подразумевает связь |
|---|---|---|---|
| 16 `~` | **S3 Расписание: «Срок удержания истёк» → S4 Бронирование: «Закрыть просроченную бронь»** | async | Закрыть соответствующую бронь, если сообщение ещё применимо к её текущему состоянию. |
| 17 | **S4 Бронирование: «Бронь отменена» → S3 Расписание: «Освободить интервал»** | async | Снять удержание или закрепление интервала, относящееся к отменённой брони. |
| 18 `+` | **S4 Бронирование: «Бронь отменена» / «Срок оформления брони истёк» → S7 Игровые сеансы: «Отменить ожидаемое посещение»** | async | Отменить ожидаемое посещение, если оно существует, и не допустить последующей фиксации неявки по этой брони. |
| 19 `~` | **S4 Бронирование: отмена оплаченной брони → S6 Платежи: «Запросить возврат»** | async | Запустить предусмотренный возврат. Этот же путь используется для поздней оплаты, если бронь уже закрыта и подтвердить её нельзя. |
| 20 `~` | **S6 Платежи: «Деньги возвращены» / «Возврат не выполнен» → S4 Бронирование: «Обработать результат возврата»** | async | Передать результат возврата, чтобы обновить его статус по брони. |
| 21 | **S6 Платежи: «Деньги возвращены» → S8 Уведомление: «Создать уведомление»** | async | Подготовить клиенту сообщение о состоявшемся возврате. |

## Обращения людей через клиентское приложение

В итоговом описании эти обращения приняты синхронными. Ответ HTTP-вызова может сообщать о принятии команды; завершение оплаты и других асинхронных процессов приходит позже.

| Откуда → куда | Тип | Что подразумевает связь |
|---|---|---|
| **Клиент → S1 Пользователь** | sync | Зарегистрироваться, изменить профиль или контакт. |
| **Клиент → S5 Тарифы** | sync | Рассчитать стоимость и получить ценовое предложение. |
| **Клиент → S4 Бронирование** | sync | Создать заявку, отменить бронь, получить состояние брони и данные для оплаты. |
| **Администратор → S2 Каталог столов** | sync | Добавить или опубликовать стол, изменить его карточку. |
| **Администратор → S3 Расписание** | sync | Задать расписание стола. |
| **Администратор → S7 Игровые сеансы** | sync | Начать или завершить игровой сеанс. |
| **Управляющий → S5 Тарифы** | sync | Опубликовать тариф. |

## Взаимодействие с внешними сервисами

На доске обозначены внешние сервисы и результаты их работы, но конкретный тип обмена `sync/async` для этих интеграций не задан.

| Откуда → куда | Что подразумевает связь |
|---|---|
| **S6 Платежи → Платёжный провайдер** | Создать операцию оплаты или запросить возврат. |
| **Платёжный провайдер → S6 Платежи** | Передать результат оплаты или возврата; вызвать соответствующую команду обработки результата. |
| **S8 Уведомление → Провайдер сообщений** | Передать уведомление для отправки клиенту. |
| **Провайдер сообщений → S8 Уведомление** | Вернуть результат отправки, который учитывается как успех или неудача. |

## Внутренние запуски по времени

| Инициатор → команда | Что подразумевает запуск |
|---|---|
| **Таймер S3 → «Завершить просроченное удержание»** | Найти и завершить удержание с истёкшим сроком. |
| **Таймер S7 → «Зафиксировать неявку»** | Проверить ожидаемое посещение и зафиксировать неявку, если оно не было начато или отменено. |

Это внутренние запуски: им не присвоен тип межсервисного обмена `sync/async`.
