## Быстрый запуск

Нужен Docker с Docker Compose v2. Из каталога проекта:

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
```

Compose создаёт 10 контейнеров: восемь приложений, PostgreSQL и RabbitMQ. Порты
доступны только на `127.0.0.1`. Базы и данные RabbitMQ сохраняются в именованных томах.
У каждого сервиса отдельные PostgreSQL-база и роль; прямого доступа в чужие базы нет.

| Сервис | Swagger | Основной ресурс |
|---|---|---|
| S1 users | http://localhost:8001/docs | `/api/users` |
| S2 catalog | http://localhost:8002/docs | `/api/tables` |
| S3 schedule | http://localhost:8003/docs | `/api/holds` |
| S4 bookings | http://localhost:8004/docs | `/api/bookings` |
| S5 pricing | http://localhost:8005/docs | `/api/quotes` |
| S6 payments | http://localhost:8006/docs | `/api/payments` |
| S7 sessions | http://localhost:8007/docs | `/api/sessions` |
| S8 notifications | http://localhost:8008/docs | `/api/notifications` |

RabbitMQ Management: http://localhost:15672, локальные учебные логин/пароль `micro` / `micro`.
Для проверки процессов есть `/health` у каждого сервиса; поле `broker_connected`
показывает текущее соединение с брокером. HTTP-приложение может принимать команды при
отсутствии брокера: новые события остаются в outbox до восстановления связи.

Поддерживается Podman с установленным `podman-compose`: замените `docker compose`
на `podman-compose`. На macOS предварительно запустите нужную Podman machine;
если машин несколько, укажите `CONTAINER_CONNECTION=<имя>`.

## Демонстрация всех восьми сервисов

Создайте отдельное окружение для клиента и тестов:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m scripts.demo
```

Скрипт создаёт уникального пользователя и стол, задаёт график и тариф, получает цену,
оформляет бронь, имитирует успешную оплату, проверяет посещение и уведомление,
отменяет бронь и завершает полный возврат. В конце выводит JSON с `result: PASS`.
Асинхронные результаты проверяются ожиданием состояния, а не фиксированными паузами.
Повторный запуск создаёт новые тестовые данные.

Платёжный и почтовый провайдеры **демонстрационные**: деньги не списываются,
email/SMS не отправляются. Учебные callbacks оплаты требуют заголовок
`X-Provider-Token: demo-provider-token` (или значение `PROVIDER_TOKEN` из `.env`).
При изменении токена задайте то же значение в окружении запуска `scripts.demo`.

## Автотесты практики 8

Для локальных тестов нужны Python 3.13, Node.js 24+ и Go 1.25+.
Python-зависимости устанавливаются из `requirements-dev.txt`; Node.js-зависимости
из lockfile; Go загружает закреплённые модули через `go.mod` и `go.sum`.

```bash
python -m pytest tests/unit tests/component --cov --cov-report=term-missing
npm --prefix common-node ci
npm --prefix common-node test
go test -race ./...
```

Python-набор проверяет S1/S2/S5/S8, общую инфраструктуру Python и варианты ПР5.
Node.js-набор проверяет S3/S7 и `common-node`; Go-набор — S4/S6 и `internal/gokit`.
Unit-тесты используют память, управляемые часы и подмену внешних HTTP-вызовов.
Компонентные проверки обращаются к реальным обработчикам каждого языка; Node.js
открывает локальный HTTP-порт. PostgreSQL и RabbitMQ этим наборам не нужны.

После запуска Compose выполните независимые от языка контрактные тесты:

```bash
RUN_HTTP_INTEGRATION=1 python -m pytest tests/integration \
  --ignore=tests/integration/test_http_persistence.py -q
```

Они обращаются по HTTP ко всем восьми процессам с настоящими PostgreSQL и RabbitMQ.
Двухфазная проверка сохранности после перезапуска описана в
[tests/integration/README.md](tests/integration/README.md). Актуальные числа тестов,
покрытие и журналы приведены в [протоколе проверок](docs/validation.md).

Чтобы обновить спецификации четырёх Python-сервисов и проверить сохранённые
контракты Node.js/Go без запуска стенда:

```bash
python -m scripts.export_openapi
```

## Принятые правила

- Начало игры с шагом 30 минут, длительность 1–4 часа, также с шагом 30 минут.
- Все даты ISO 8601 с часовым поясом; внутри хранятся в UTC. Денежные суммы — целые копейки, `RUB`.
- Удержание действует до 10 минут, не позднее начала игры. Ценовое предложение — 10 минут.
- Бронь подтверждается после оплаты и успешного закрепления удержания.
- Отмена разрешена до начала. Полный возврат — при отмене за 2 часа и более.
- Опоздавшая оплата закрытой неоплаченной брони возвращается полностью; бронь не восстанавливается.
- Начать игру можно в первые 15 минут. Затем фиксируется неявка без возврата.
- Подтверждённые интервалы не освобождаются таймером удержаний или ранним завершением игры.

Проверка стола в S5 через S2 добавлена к исходной Markdown-диаграмме: это полезная
проверка существования/публикации и требуемый для владельца S2/S5 межсервисный HTTP-вызов.
Остальные исходящие вызовы участников: S8→S1, S3→S2/S7→S4, S4→S1/S5/S3.

## Ограничения учебной реализации

Авторизация клиентов и административных операций не реализована; стенд рассчитан
на локальную демонстрацию. Токен callback не заменяет полноценную подпись провайдера.
PostgreSQL хранит состояние каждого сервиса, inbox и outbox в одной JSON-записи
с блокировкой `SELECT FOR UPDATE`. Это обеспечивает локальную атомарность,
но сериализует операции сервиса; для нагрузки следует выделить таблицы агрегатов.

Доставка событий — at least once; inbox предотвращает повторное применение одного
`event.id`. После трёх неудачных обработок событие попадает в DLQ, где требуется
разбор причины и ручной повтор. История inbox/outbox и доменных объектов не архивируется.
Сбой между удалённым удержанием и сохранением новой брони может оставить временное
удержание без брони; его снимает таймер. Полная сохранённая сага оформления не реализована.
Подробности и границы устойчивости описаны в практике 7.

Остановка без удаления данных:

```bash
docker compose down
```

Команда `docker compose down -v` дополнительно удаляет учебные базы и очередь;
используйте её только для намеренного сброса стенда.
